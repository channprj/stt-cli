# 보안 감사 — 2026-09-30

## 범위와 결론

조사 시작점은 `da05f3cc1bf7bc43155c37ee25e9f6ab4c405b6a`이며, 작업 트리는
깨끗하고 `main`과 `origin/main`이 일치했다. 원격 브랜치·태그를 가져온 뒤
전체 23개 커밋, 태그 2개, 커밋 메시지, Git에 저장된 파일 객체 80개와 현재
소스·문서·스크립트·워크플로·의존성 잠금 파일을 검사했다.

**검사 범위에서 실제 API 키, 토큰, 개인키 노출은 검출되지 않았다.**
Gitleaks 8.30.1의 전체 이력 검사와 파일 검사에 더해, Git 객체 전체 및 커밋
메시지를 별도로 검사했다. `.env`, 자격증명 파일, 개인키 이름의 과거 경로도
점검했으며 후보가 없었다. `git fsck --full --no-reflogs --unreachable`에서
도달 불가능한 객체는 보고되지 않았다. 예제용 테스트 문자열과 GitHub
`secrets` 참조는 실제 자격증명 값이 아니다.

이 결과는 저장소 밖의 셸 기록, 사용자 계정의 자격증명 파일, GitHub Secrets
실제 값, 과거 실행 로그·아티팩트, 삭제된 원격 참조, 다른 복제본·포크까지
포괄하는 유출 부재 증명이 아니다. 실제 제공자 계정이나 녹음을 사용하지
않았고 키 유효성 확인 요청도 보내지 않았다.

TLS 항목은 [RUSTSEC-2026-0285](https://rustsec.org/advisories/RUSTSEC-2026-0285.html)
(CVSS 5.3)에 근거한다. 이 취약점이 네트워크 공격자의 임의 핸드셰이크 변조나
인증 우회를 허용한다는 주장은 하지 않는다. `chacha20`은 감사 도구가 보고한
yanked 상태를 해소한 것이며 별도 취약점이 확인되었다는 뜻은 아니다.

CI 조치는 [GitHub의 Actions 보안 지침](https://docs.github.com/en/actions/reference/security/secure-use)을
따른다. CSV 방어는 [OWASP 설명](https://community.owasp.org/attacks/CSV_Injection)처럼
스프레드시트 재저장 과정에서 해제될 수 있으므로, 원문 교환에는 JSON을
사용하고 외부 문자열 열은 텍스트로 가져와야 한다.

## 운영상 한계

키 저장은 암호화되지 않는다. 같은 OS 계정이나 관리자 권한을 탈취한 공격자,
신뢰할 수 없는 PATH·설정 상위 디렉터리는 별도 보호가 필요하다. SIGKILL,
정전, 네트워크 단절에서는 로컬·원격 정리가 완료되지 않을 수 있다. 과거
버전이 남긴 공용 임시 디렉터리는 다른 실행의 파일을 지울 위험이 있어 자동
삭제하지 않는다. 삭제 경고에 나온 Soniox 리소스나 과거 오디오 잔존 여부는
소유자가 확인해야 한다.

릴리스 게시·Homebrew tap 쓰기 경로는 정적 검사와 기존 로컬 릴리스 도구
테스트로 검증했다. 감사 중 새 릴리스 생성·배포는 수행하지 않았다. 외부
ffmpeg 등 실행 도구의 모든 버전이나 제공자의 서버 내부 보안은 본 감사의
검증 범위에 포함되지 않는다.
